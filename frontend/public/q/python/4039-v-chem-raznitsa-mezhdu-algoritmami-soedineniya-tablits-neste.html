В чем разница между алгоритмами соединения таблиц: Nested Loop, Hash Join и Merge Join в PostgreSQL?

Тренировать в Telegram-боте →

💡 Краткий ответ для собеседования
Nested Loop — для каждой строки внешней таблицы ищет совпадения во внутренней (идеален при наличии индекса на внутренней таблице и малом внешнем наборе). Hash Join строит хэш-таблицу по меньшей таблице в памяти (work_mem) и сканирует вторую (идеален для больших несортированных наборов при равенстве =). Merge Join соединяет два предварительно отсортированных набора за один линейный проход (идеален при наличии B-Tree индексов).

Варианты ответа в приложении:

  • A. Nested Loop — вложенный цикл по индексу; Hash Join — хэш-таблица в памяти по меньшей таблице; Merge Join — слияние отсортированных потоков Правильный
  • B. Nested Loop работает только с внешними API, а Hash Join — только с локальными файлами
  • C. Merge Join объединяет строки случайным образом без проверки условий ON
  • D. Все три алгоритма устарели и заменены нейросетевым оптимизатором
