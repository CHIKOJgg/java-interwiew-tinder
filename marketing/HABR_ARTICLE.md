Каждый, кто хоть раз готовился к техническому собеседованию на Java или Python (особенно уровня Middle/Senior), знает это чувство.

Ты открываешь GitHub-репозиторий типа `awesome-java-interview-questions` на 400 вопросов или PDF-методичку 2019 года. На 15-м вопросе («*В чём разница между String, StringBuilder и StringBuffer?*») начинает клонить в сон. На 40-м («*Как устроен ConcurrentHashMap в Java 8?*») ты понимаешь, что прочитал абзац три раза и ничего не запомнил, потому что пассивное чтение текста не тренирует воспроизведение знаний под стрессом.

А на реальном собеседовании тимлид спрашивает не абстрактное определение из Википедии, а:
> *«У нас сервис падает с OOM: Metaspace, хотя Xmx ещё 4 гигабайта свободно. Что происходит и куда ты пойдешь смотреть?»*

Полгода назад, готовясь к очередному раунду собеседований в бигтех, я поймал себя на мысли: почему мы учим иностранные языки в Duolingo за 5 минут в метро, а к собеседованиям на 200–400k ₽ готовимся по унылым таблицам в Excel или статическим лонгридам?

## Проблема «шпаргалок»: иллюзия компетентности

Главный враг любого кандидата — **иллюзия компетентности** (Recognition vs Recall).
Когда ты читаешь готовый ответ в шпаргалке:
> *«А, ну да, в Java 8 HashMap при коллизиях больше 8 элементов превращает бакет в красно-чёрное дерево, если размер массива >= 64. Я это знаю!»*

Мозг ставит галочку «Я это знаю». Но когда на интервью тебя просят:
> *«А почему именно красно-чёрное, а не AVL? И почему порог равен 8, а не 4 или 16?»*

Наступает ступор. Потому что в памяти остался лишь след от узнавания, а нейронная связь для активного извлечения (active recall) не сформировалась.

### Как это решает формат свайпов:
1. **Вопрос перед глазами без подсказок.** Ты видишь задачу / вопрос и обязан сначала дать ответ себе в голове или выбрать вариант.
2. **Мгновенная калибровка:**
   - Свайп вправо (`Знаю`) — интервал до следующего показа увеличивается.
   - Свайп влево (`Не знаю / Сомневаюсь`) — вопрос падает в пул повторения на завтра и послезавтра.
3. **Краткий тезисный ответ («как отвечать на собесе»):** 2–3 предложения без воды, которые можно произнести вслух за 20 секунд.
4. **Кнопка «Разбор ИИ»:** если вопрос сложный (например, нюансы работы G1 GC или асинхронщина в Python AsyncIO), модель на лету раскладывает теорию, подводные камни, частые заблуждения и даёт реальный пример кода.

## Архитектура: как всё устроено внутри

Приложение проектировалось с прицелом на скорость: если карточка свайпается с задержкой даже в 100 мс — пользователь теряет состояние «потока».

```
                     ┌──────────────────────────────┐
                     │   Telegram Mini App (React)  │
                     │  + Tailwind / Lucide / PWA   │
                     └──────────────┬───────────────┘
                                    │ HTTPS (InitData HMAC)
                                    ▼
                     ┌──────────────────────────────┐
                     │   Node.js (Express / ESM)    │
                     │  Rate Limiting, Auth, Routes │
                     └──────┬────────────────┬──────┘
                            │                │
            Connection Pool │                │ Caching (60s TTL)
                            ▼                ▼
            ┌──────────────────────┐  ┌─────────────┐
            │ PostgreSQL (Railway) │  │ Redis Cache │
            │ Questions, Swipes,   │  │ Sessions,   │
            │ Progress, Payments   │  │ AI cache    │
            └──────────────────────┘  └─────────────┘
```

### 1. Авторизация без логинов и паролей
Поскольку 90% пользователей открывают приложение внутри Telegram, вход происходит в 0 кликов. Telegram передаёт строку `window.Telegram.WebApp.initData`.
На бэкенде мы валидируем криптографический HMAC-SHA256 хеш с использованием секретного ключа бота:

```javascript
import crypto from 'crypto';

export function validateTelegramInitData(initData, botToken) {
  const urlParams = new URLSearchParams(initData);
  const hash = urlParams.get('hash');
  urlParams.delete('hash');

  const params = Array.from(urlParams.entries())
    .map(([key, value]) => `${key}=${value}`)
    .sort()
    .join('\n');

  const secretKey = crypto.createHmac('sha256', 'WebAppData').update(botToken).digest();
  const calculatedHash = crypto.createHmac('sha256', secretKey).update(params).digest('hex');

  return calculatedHash === hash;
}
```
Если пользователь заходит из обычного браузера (например, нашел вопрос в Google), доступна авторизация по Google One Tap или одноразовому коду на Email.

### 2. Пул соединений и защита от перегрузок
В первой версии мы столкнулись с классической проблемой: 100 человек открывают приложение одновременно в Telegram-канале, каждый делает по 20 свайпов за минуту — база PostgreSQL захлёбывается от соединений.

Мы оптимизировали это тремя вещами:
- **Batching свайпов:** результаты ответов не пишутся синхронно на каждый свайп в отдельной транзакции, а отправляются пакетами или с минимальным оверхедом через оптимизированный upsert в Postgres.
- **Статический кэш колод:** колоды вопросов по темам (Java Core, Spring, Multithreading, Python Core, Django, FastAPI) кэшируются на уровне Redis и локального хранилища браузера (30 минут TTL).
- **Пул соединений (pg-pool)** с агрессивным таймаутом простоя и переиспользованием клиентов.

## Платёжка: почему Telegram Stars — это магия для микро-SaaS

Раньше для приёма платежей за подписку в СНГ и за рубежом приходилось настраивать несколько шлюзов: Stripe для зарубежных карт, ЮKassa/CloudPayments для РФ карт, крипту (TON/USDT).
У каждого шлюза:
- Редирект в отдельное окно браузера.
- Ввод 16 цифр карты, CVC и подтверждение через SMS.
- Конверсия на шаге ввода карты падала на 60–75%.

Летом 2024 года Telegram внедрил **Telegram Stars**.
В приложении это выглядит так:
1. Пользователь нажимает «Оформить Pro».
2. Бэкенд вызывает `createInvoiceLink` бота с ценой в звёздах (например, 250 Stars за месяц).
3. Фронтенд вызывает нативный метод Telegram SDK:
```javascript
window.Telegram.WebApp.openInvoice(invoiceLink, (status) => {
  if (status === 'paid') {
    // Мгновенная активация Pro без перезагрузки экрана
    updateUserSubscription();
  }
});
```
4. Внутри Telegram всплывает нативная шторка оплаты в 1 клик с баланса Apple Pay, Google Pay или банковской карты.
Конверсия в оплату выросла в разы просто за счёт устранения трения (frictionless payment).

## База вопросов: 800+ задач с реальных собеседований

Мы принципиально отказались от генерации «мусорных» вопросов роботом в вакууме.
Каждый вопрос в базе разбит по грейдам (Junior / Middle / Senior) и актуальным темам:

- **Java:** Java Core, Collections internals, Memory Model & JVM, Concurrency (JMM, CAS, AQS, synchronized), Spring Boot (AOP, Transactions, Bean Lifecycle), Hibernate/JPA, Kafka, SQL & индексы.
- **Python:** Data model (изменяемость, хэшируемость), генераторы, декораторы, метаклассы, GIL, AsyncIO, фреймворки (FastAPI, Django, Flask), Celery, SQLAlchemy.
- **System Design & Архитектура:** Rate limiting, кэширование (Cache-Aside, Write-Through), шардирование, репликация, CAP-теорема, идемпотентность API.

Пример вопроса уровня Middle:
> **Вопрос:** *В чём разница между `@Transactional(propagation = Propagation.REQUIRED)` и `REQUIRES_NEW` в Spring? Что произойдет, если внутренний метод выбросит RuntimeException?*  
> **Краткий ответ для собеса:** `REQUIRED` использует существующую транзакцию или создает новую; исключение во внутреннем методе помечает всю транзакцию как `rollback-only`. `REQUIRES_NEW` приостанавливает текущую транзакцию и создает независимую физическую; откат во внутренней транзакции не обязательно откатывает внешнюю, если перехватить исключение.
