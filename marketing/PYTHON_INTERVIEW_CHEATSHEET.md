## 1. CPython Memory Management: Счётчик ссылок и циклический GC

### Вопрос с собеседования:
*«Как работает управление памятью в Python? Почему счётчика ссылок (Reference Counting) недостаточно?»*

### Разбор:
Основной механизм управления памятью в CPython — это **счётчик ссылок (`ob_refcnt`)**.
Каждый раз, когда объект присваивается переменной или передается в контейнер, счётчик увеличивается на 1. Когда переменная выходит из области видимости или удаляется через `del`, счётчик уменьшается. Когда счётчик становится равен **0**, память под объект освобождается немедленно.

### Проблема циклических ссылок:
```python
class Node:
    def __init__(self):
        self.cycle = None

a = Node()
b = Node()
a.cycle = b
b.cycle = a

del a
del b
# Счётчик ссылок для обоих объектов равен 1, но доступа к ним больше нет!
```
Если бы был только счётчик ссылок, произошла бы утечка памяти.
Для решения этой проблемы в CPython встроен **Cyclic Garbage Collector (gc)**:
- Он отслеживает только составные объекты (контейнеры: списки, словари, пользовательские классы). Не отслеживает атомарные типы (числа, строки).
- Использует **3 поколения объектов (Generations 0, 1, 2)** по принципу: молодые объекты умирают чаще всего.
- Периодически ищет циклические графы ссылок и принудительно их очищает.

## 2. GIL (Global Interpreter Lock): Зачем он нужен и как жить с ним

### Вопрос с собеседования:
*«Зачем в Python существует GIL? В каких случаях threading ускоряет выполнение, а в каких замедляет?»*

### Разбор:
**GIL** — это мьютекс, который предотвращает одновременное выполнение байткода CPython несколькими потоками операционной системы.

**Зачем он нужен:**
- Защита внутренней структуры памяти CPython (в первую очередь того самого `ob_refcnt`) от состояния гонки (race conditions) без накладных расходов на тонкогранулярные блокировки вокруг каждого объекта.
- Простота интеграции с C-библиотеками, которые изначально не были потокобезопасными.

### CPU-bound vs I/O-bound:
- **I/O-bound задачи (сеть, файлы, запросы к БД):** Потоки (`threading`) **ускоряют** работу! При выполнении системного вызова (например, ожидание ответа от сокета) поток отпускает GIL, давая другим потокам работать.
- **CPU-bound задачи (вычисления, обработка видео, сжатие):** Потоки **замедляют** работу из-за накладных расходов на постоянное переключение контекста и борьбу за GIL. Для вычислений нужно использовать `multiprocessing` (отдельные процессы со своими копиями Python VM) или компилируемые расширения (Cython, Rust, C++).

## 3. AsyncIO: Как устроен Event Loop и корутины

### Вопрос с собеседования:
*«Что такое корутина (coroutine) под капотом в Python? Что произойдет, если внутри async def вызвать time.sleep(5)?»*

### Разбор:
- Корутина — это специальный тип генератора. Под капотом конструкция `async def` создает функцию, возвращающую объект корутины, а оператор `await` работает аналогично `yield from`, делегируя управление планировщику (Event Loop).
- Event Loop крутится в **одном потоке** и по очереди проверяет готовность файловых дескрипторов (через `epoll` в Linux, `kqueue` в macOS, `IOCP` в Windows).

### Фатальная ошибка:
Если вызвать `time.sleep(5)` внутри асинхронного обработчика (например, в FastAPI или aiohttp), **весь Event Loop заблокируется на 5 секунд**! Все остальные запросы от сотен пользователей зависнут.
**Правильно:** использовать `await asyncio.sleep(5)` или запускать блокирующий код через `asyncio.to_thread(sync_func)`.

## 4. Декораторы с аргументами и сохранение метаданных

### Вопрос с собеседования:
*«Напишите структуру декоратора, принимающего параметры. Зачем нужен @functools.wraps?»*

### Шаблон правильного декоратора:
```python
import functools
import time

def retry(attempts=3):
    def decorator(func):
        @functools.wraps(func)  # Сохраняет __name__, __doc__, __annotations__
        def wrapper(*args, **kwargs):
            for i in range(attempts):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if i == attempts - 1:
                        raise e
                    time.sleep(1)
        return wrapper
    return decorator
```

Если не применить `@functools.wraps(func)`, имя декорированной функции `func.__name__` станет `'wrapper'`, а документация `__doc__` сотрется, что сломает логирование, фреймворки валидации (Pydantic, FastAPI) и автодокументацию Swagger.

## 5. Мутабельные аргументы по умолчанию: Ловушка `def f(x=[])`

### Вопрос с собеседования:
*«Что выведет код и почему?»*
```python
def append_to(element, target=[]):
    target.append(element)
    return target

print(append_to(1))
print(append_to(2))
```

### Разбор:
Вывод будет:
`[1]`
`[1, 2]` — не `[2]`!
В Python значения аргументов по умолчанию вычисляются **один раз в момент определения функции (def)**, а не при каждом её вызове. Список `target` привязывается к объекту функции в атрибуте `__defaults__` и разделяется между всеми вызовами.

**Каноничное решение:**
```python
def append_to(element, target=None):
    if target is None:
        target = []
    target.append(element)
    return target
```
